### Direction (options for the maintainer, not ranked against the bugs above)

- **Ship a minimal authenticated shell.** When Supabase is configured, `src/lib/supabase/middleware.ts:55-64` gates every non-`/auth` route behind login, yet there is no sign-out UI anywhere and `signOut` in `src/app/auth/login/actions.ts:60-65` is exported but unused. A header with the user's email and a sign-out button (Server Component reading `supabase.auth.getUser()`, form posting to `signOut`) would make the auth flow round-trip out of the box. Effort S-M. Trade-off: adds opinionated layout to a boilerplate whose home page is currently a bare Calendar demo.
- **Make the database conventions executable.** CLAUDE.md devotes two sections to table naming, RLS policy shape and migration file format, and a `supabase` skill is installed, but `supabase/` contains only a `.gitignore`. A `supabase/config.toml` plus one example migration (a `public.profiles` table with the four per-operation RLS policies the doc prescribes) would turn prose into a copyable exemplar. Effort M. Trade-off: the example must be kept in sync with the doc or it becomes finding-4-style drift.
- **Choose one toast system and mount it in `Providers`.** Base UI `toast.tsx` (new this refresh) and `sonner.tsx` both export `Toaster`; CLAUDE.md already says "mount one, not both". Mounting the chosen one in `src/components/providers.tsx` and deleting the other removes a decision every new project would otherwise make late. Effort S. Trade-off: sonner has richer built-ins (promise toasts, rich colors); Base UI toast keeps the dependency surface at zero.

## Findings considered and rejected

- **Static Calendar month on the home page (finding 8)**: the page is a placeholder demo that any real project replaces on day one; fixing it properly means either forcing dynamic rendering of `/` (`await connection()` in a Server Component) or removing the demo. Not worth a plan; whoever replaces the home page resolves it.
- **Prettier / formatting consistency (finding 9)**: real but the fix reformats most of `src/` outside `components/ui`, which is exactly the churn a fresh project would rather do once on its own terms. Recorded here so it is not re-audited; if wanted, the shape is: add `prettier` + `prettier-plugin-tailwindcss` as devDependencies, a `.prettierrc` matching the shadcn style (no semicolons, double quotes), a `format:check` script in CI, and one reformat commit.
- **Middleware `startsWith('/login')` exclusion is dead** (`src/lib/supabase/middleware.ts:57`; there is no `/login` route): harmless, one token; fold into any future middleware edit rather than planning it.
- **Home page is auth-gated when Supabase is configured**: by design of the upstream Supabase SSR template; surfaced under direction instead.
- **`signOut` exported but unused**: intentional public surface for a boilerplate; surfaced under direction.
- **No CSP / security headers in `next.config.ts`**: a boilerplate cannot know its deployment's script/connect sources; adding a default CSP that breaks the first third-party script is worse than none. Revisit when the project has a real origin list.
- **CI `concurrency` group to cancel superseded runs**: trivial nicety, no measurable cost today.
- **TypeScript 7 upgrade**: verified blocked (typescript-eslint peer `>=4.8.4 <6.1.0`); already documented in CLAUDE.md "Dependency notes".
- **"supabase middleware ignores headers arg"** (from the handoff candidate list): `updateSession(request)` has no headers parameter and `NextResponse.next({ request })` is the documented shape; nothing to fix.
